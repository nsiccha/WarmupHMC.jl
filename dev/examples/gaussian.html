Gaussian calibration ​

The target is a standard bivariate Gaussian with independent, dimensionless coordinates. There are no observations or fitted hyperparameters: its analytic mean and variance are known. That makes it a useful calibration case for the target interface, draw orientation, and interpretation of diagnostics before using a model whose posterior is unknown. This example examines one recorded run, not a comparison of sampling algorithms or a claim about difficult posterior geometry. The fit is cached as a small summary; the code receipt below binds that summary to the target and random seed, and records the sampler source.

Target and run ​

The object declares its dimension and first-order capability, then supplies a log density and gradient. Dropping the Gaussian normalization constant leaves the target distribution unchanged. The gradient has the same length and coordinate order as the input vector. No automatic differentiation package or nonlinear coordinate map is needed for this target. For a hierarchical target, the reparametrization guide explains how to add a map while keeping the model and sampler coordinate conventions explicit.

The following program is the exact source executed for the cached fit. The documentation build checks its hash before showing its saved output, and the receipt records the package source that ran it. Sampling is deliberately excluded from the build and CI; the remaining calculations and figure construction execute at build time.

julia
using WarmupHMC, Random
import LogDensityProblems as LDP

struct Gaussian end
LDP.dimension(::Gaussian) = 2
LDP.capabilities(::Type{Gaussian}) = LDP.LogDensityOrder{1}()
LDP.logdensity(::Gaussian, x) = -sum(abs2, x) / 2
LDP.logdensity_and_gradient(p::Gaussian, x) = (LDP.logdensity(p, x), -x)

result = adaptive_warmup_mcmc(Xoshiro(71), Gaussian();
    n_draws=1000, monitor_ess=true, progress=nothing)
size(result.posterior_position)

(2, 1000)

The rows are model coordinates and the columns are retained draws. The output reports the actual shape rather than assuming the requested floor is the exact count. With a nonlinear wrapper, returned positions would already be in model coordinates; applying the map again would change the sample. Raw warm-up state and gradients have a different coordinate contract, described in Sampling.

Coordinate view ​

A fixed scale transformation illustrates the distinction between the sampler's position and the model's position. This evaluates a density without fitting or requiring an AD backend. The Boolean output checks that the wrapper includes the Jacobian for a non-centered first coordinate:

julia
rule = Reparametrization(PartiallyCentered(1.0), PartiallyCentered(0.0), 0.0, log(2.0))
wrapped = ReparametrizedProblem(IndexedReparametrization([1 => rule]), Gaussian())
x = [0.3, -0.4]
y = [2x[1], x[2]]
isapprox(LDP.logdensity(wrapped, x), log(2.0) + LDP.logdensity(Gaussian(), y))

true

The sampled run above uses the original Gaussian directly. The view demonstrates coordinate bookkeeping; it is not an additional fit or a performance comparison.

Coordinate summaries ​

Compare each estimated mean and standard deviation with the analytic target. The table also shows a Monte Carlo standard error for the mean, estimated as the sample standard deviation divided by the square root of the reported effective sample size. That estimate describes simulation uncertainty under the chain's dependence structure. It is not posterior uncertainty about the coordinate, and it is not evidence that all modes of an unknown target have been explored.

Diagnostics ​

The following values describe the retained sample and the work the sampler recorded. Inspect divergences alongside moments rather than treating an accurate mean as a substitute for trajectory diagnostics. A chain can have a plausible mean while missing important regions of its target. Conversely, a finite run need not reproduce an analytic moment exactly even when its transitions behave as intended. For an unfamiliar model, repeat the analysis with independent initializations and compare chains before combining their draws.

julia
diagnostics = cache["diagnostics"]
ManualCache.table(["Diagnostic", "Recorded value"], [

    ["Step size", round(diagnostics["stepsize"]; digits=4)],
    ["Selected linear transformation", diagnostics["transformation"]],

Gradient evaluations are counts, not seconds. The retained-sampling counter belongs to the transitions behind the returned draw matrix. The run counter includes discarded epochs and step-size adaptation but excludes Pathfinder and the initial step-size search. Dividing the run counter by the retained draw count therefore answers a different cost question from dividing the sampling counter by that count. Neither ratio alone measures the accuracy of a posterior estimate; compare simulation error as well as work when assessing a sampler.

Continuation ​

The same cached run collection includes a checkpoint demonstration. Its program and visible before/after result are in Checkpoints. It saves an initial sample, restores the same target with a larger draw floor, and compares the prefix of the continued matrix with the original draws. That comparison checks continuity of the retained sample, not the validity of resuming after changing data or a likelihood. Such changes define a different target and are not established by a matching dimension.

For a production analysis, keep the model inputs and sampler configuration alongside the checkpoint. Select a persistent path and preserve the dependency environment needed to read its serialized state. The temporary directory in the demonstration is appropriate only because the program checks its result before the directory is removed. The saved summary below is sufficient to rebuild this page, but intentionally cannot resume the fitted chain because it contains no draws, RNG state, or checkpoint payload.
