Adaptive sampling ​

The signatures below use placeholder arguments and are not standalone programs. The Gaussian example supplies a complete target and run.

Arguments, return fields, initialization, and checkpoint controls for the adaptive entry points. For a worked call, see Gaussian calibration.

Independent chains ​

WarmupHMC.adaptive_warmup_mcmc Function
julia
adaptive_warmup_mcmc(rng, lpdf; kwargs...)
adaptive_warmup_mcmc(rngs::AbstractArray, lpdf_or_lpdfs; parallel=true, kwargs...)

Run windowed adaptive NUTS warm-up + sampling against the LogDensityProblems-compatible lpdf, returning a NamedTuple of posterior positions/gradients plus diagnostics. Multi-chain dispatch broadcasts over rngs and (optionally) per-chain log densities.

The warm-up procedure is windowed and inspired by Stan's and nutpie's warm-up procedures, but differs in several important ways:

  • Initializes via Pathfinder (LBFGS-based variational approximation).

  • Warm-up windows target a number of GRADIENT EVALUATIONS rather than MCMC transitions. Default 1000, doubled after every window.

  • Uses POSITIONS AND GRADIENTS (like nutpie), plus one state from every NUTS tree traversal. The state is drawn from the exact marginal proposal probabilities induced by all leaf Hamiltonian errors, including the probability of staying at the initial state. Up to recording_target such states are kept.

  • Learns three candidate linear transformations in parallel at the end of every warm-up window:

    • Pathfinder's initial transformation + an updated diagonal scaling,

    • A standard diagonal "mass matrix",

    • A novel, adaptive sequence of Householder reflections followed by diagonal scaling.

    Selection minimises loss(p', g') = sum(abs2(log(std(p') * std(g')))) on the transformed intermediate positions/gradients — zero for an uncorrelated Normal target.

  • Adapts step size for only the first stepsize_adaptation_limit transitions per window (default 50), then freezes the step size and treats subsequent transitions as posterior samples.

  • Stops warm-up adaptively: if the marginal-scale condition number drops below variance_cond_target (default 2.0), no new window starts. linear_restart_source=:halo preserves the existing thinned-halo criterion. Opt-in :nuts_weighted uses each trajectory's exact NUTS proposal distribution, while :all_good_leaves weights every eligible noninitial leaf equally. linear_trajectory_weighting=:unit gives each trajectory or eligible leaf unit exposure; :stepsize multiplies those weights by the trajectory step size. There is no adaptation-phase or validity-fraction branch: unit versus step-size weighting is an empirical choice throughout.

  • Ends as soon as the retained draws reach n_draws, without running that test on the window that got there, unless more than max_divergent_fraction (default 0.5) of the retained draws diverged. Then the kernel no longer fits where the chain is, typically because the chain moved on from the region the kernel was adapted in, and warm-up restarts there instead, at most twice per run. Past that bound the draws are returned with a warning: re-adapting in place cannot rescue a chain whose position is the problem, and rerunning is the caller's job.

  • Opt-in (divergence_tolerance below 1): when more than divergence_tolerance of the draws of that window diverged and the gate did not restart, halves the step size, drops the draws and samples n_draws new ones under the same metric from where the chain is, without re-adapting anything. For targets whose curvature varies strongly everywhere, such as the regularised horseshoe. Each halving costs about twice the gradient evaluations per draw. It also records the acceptance rate the halved step size achieves (the mean acceptance statistic of its draws, estimated as 0.8 → 0.95 until measured), and every later step-size adaptation targets that rate instead of target_acceptance_rate, under whatever metric and centering a restart picks. At most three halvings per run; past that the draws are returned with a warning.

If nonlinear_adapt=true (the default) and lpdf wraps a ReparametrizedProblem, the active IndexedReparametrization is optimised at the end of every warm-up window, and posterior samples are transformed back to the original parametrization before returning.

init kwarg

init controls per-chain initialization:

  • missing (default) — random Uniform(-2, +2) start, then Pathfinder.

  • a Real — random Uniform(-init, +init) start, then Pathfinder.

  • a Distribution — sample from it, then Pathfinder.

  • an AbstractVector — use as the unconstrained starting position, then Pathfinder.

  • a PathfinderResult — take the first draw, skip running Pathfinder.

  • a NamedTuple — interpret as a pre-built initialization and skip Pathfinder entirely. The required keys are position, an unconstrained vector of target dimension, and squared_scale, either a same-length vector of diagonal variances or a full target-dimension × target-dimension matrix. A Diagonal matrix is accepted. Optional extra keys are preserved.

A start that runs Pathfinder is where its optimizer begins, not where the chain is kept: the chain starts from a draw of the best Gaussian fit along the L-BFGS path, which can lie in a different basin from the start. The first L-BFGS step has no curvature information yet, and its line search can carry a poor start tens of unconstrained units. To begin warm-up exactly at a position, pass the NamedTuple form, e.g. (; position = q, squared_scale = ones(length(q))).

An AbstractVector start may be a stationary point of the log density (a mode: a MAP estimate, an empirical-Bayes estimate). L-BFGS has nothing to do there, so Pathfinder is run from the start plus a Gaussian jitter instead (standard deviation 0.05 per coordinate, then 1.0 if that run yields no fit), and the chain starts from that run's draw with its metric, as from any other start. The same retry serves a finite start from which Pathfinder's first line search fails. If no jittered run yields a fit either, the chain starts exactly at the given position with a unit diagonal metric, with a warning. WarmupHMC's own random starts redraw on a failure instead.

The start is a point at which lpdf is finite. Pathfinder's fit is a Gaussian, so its draw can land outside a bounded support, or where the model answers NaN; such a draw is replaced by a fresh draw from the same fit, up to ten times, and failing that by the L-BFGS iterate the fit was made at (then the other iterates, from the trajectory's end back to the start), with a warning. The fit's covariance gives the initial metric either way, and a run whose first draw is finite is unchanged.

Finite is not enough on a target whose scales span more than Pathfinder's fit accepts, such as a collapsed variance beside normal ones: Pathfinder drops the L-BFGS curvature pairs above 1e12, and its fit is then far too wide. Such a fit is unusable, neither its draw nor its scale is used: when its covariance is far wider than a curvature its own L-BFGS trajectory measured, or when the log density at its draw lies more than 10 (d + 10) nats below what the fit predicts. Pathfinder then runs again from the same start on the target rescaled by a diagonal estimated from that trajectory, and the chain starts from that run's draw with its metric; if that run is unusable too, the chain starts at the first run's fit iterate with that diagonal as its metric, with a warning. A run whose fit passes both checks is unchanged.

When Pathfinder's inverse-Hessian fit is not positive definite (a PosDefException, typically from L-BFGS stalling on a kink of the log density, such as an fmin in the model), the fit is redone on the longest prefix of the L-BFGS trajectory that factorizes, with a warning naming the iteration.

For the multi-chain method, pass either a scalar to broadcast or a Vector of length length(rngs) for per-chain initial values. There is no separate initial_params kwarg.

The multi-chain method and lpdf

adaptive_warmup_mcmc(rngs, lpdf) gives each chain its own deepcopy(lpdf), exactly as cooperative_warmup_mcmc does, so chain i is byte-identical to running that chain on its own and the lpdf you pass is never mutated. This matters when the lpdf carries adaptation state — a ReparametrizedProblem's IndexedReparametrization is optimised in place at every window boundary — and it is why the chains do not have to share one centering.

Pass lpdfs::AbstractArray instead (adaptive_warmup_mcmc(rngs, lpdfs)) to control the per-chain problems yourself: independently built problems for independent adaptation, or fill(lpdf, n) to deliberately share one object.

Selected keyword arguments

  • n_draws=1000 — number of posterior draws to collect.

  • n_evaluations=1000 — gradient-evaluation budget for the first window; doubled each subsequent window.

  • recording_target=1000 — maximum number of acceptance-weighted NUTS leaf positions/gradients to keep.

  • stepsize_adaptation_limit=50 — per-window cap on step-size adaptation transitions.

  • target_acceptance_rate=0.8, max_tree_depth=10 — standard NUTS knobs.

  • max_reflections=16 — the most Householder reflections each window's :adaptive metric fit may add. Each reflection rotates the coordinates that are still badly fitted, so storing and applying the metric costs O(d · max_reflections). Raise it for a target with many strongly correlated blocks of parameters (one reflection decorrelates roughly one direction); typemax(Int) removes the bound.

  • nonlinear_adapt=true — whether to activate the reparametrization hooks (no-op when lpdf carries no reparametrization).

  • nonlinear_evidence=:linear_pool — evidence used to fit the nonlinear reparametrization. The default preserves the existing bounded halo fit. :all_good_leaves streams every noninitial leaf whose log Hamiltonian error exceeds nonlinear_good_leaf_threshold=log(1e-2), with equal within-trajectory weight. :nuts_weighted streams every leaf with its exact marginal NUTS proposal probability. Neither streaming mode retains leaves after the current trajectory.

  • nonlinear_trajectory_weighting=:unit — whole-trajectory multiplier for a streaming evidence mode, independent of the selected evidence source. The only alternative is :stepsize; a policy never changes when step-size adaptation ends. These settings change only the nonlinear fit: selection/application remains subordinate to a restart independently requested by the linear criterion.

  • variance_cond_target=2.0 — restart threshold on the marginal-scale condition number. With nonlinear_adapt=true it also decides whether the centering is refit, since that happens only at a restarting window. The scales are computed per coordinate in the active linear transformation's frame, so two square roots of the same metric can restart differently.

  • max_divergent_fraction=0.5 — the divergence gate on the window that reaches n_draws: when more than this fraction of the retained draws diverged, warm-up restarts instead of returning them (at most twice per run, see above). 1.0 switches it off; 0 restarts on any divergent draw.

  • divergence_tolerance=1.0 — opt-in step-size halving on the same window: when more than this fraction of the retained draws diverged, the step size is halved and the draws are resampled (at most three times per run, see above). 1.0 (default) switches it off; 0 halves on any divergent draw. The returned stepsize_halvings says how often it fired, stepsize is the halved value and effective_target_acceptance_rate the rate later adaptation targets (the call's target_acceptance_rate when it never fired): pass it as target_acceptance_rate to the next fit of the same model to start there.

  • linear_restart_source=:halo — source for that condition number. The running alternatives above replace (rather than supplement) the halo-only criterion and retain sum(w) plus sum(w^2) for general weighted moments.

  • linear_trajectory_weighting=:unit — trajectory exposure for a running source; set to :stepsize to use step-size exposure. :halo requires :unit, because it has no trajectory weights to modify.

  • linear_metric_fallback=true — for an opt-in running estimator, if a restart keeps the diagonal family and nonlinear parametrization unchanged, apply the running transformed marginal correction to that diagonal metric. Other families continue to use their ordinary halo fit.

  • progress=nothing, description="MCMC", monitor_ess — progress and diagnostic reporting via Treebars. Treebars.request_interrupt! on the node passed here (or on one chain's node, or an ancestor) stops the affected chains at their next checkpoint boundary exactly as a callback returning true would: partial draws kept, no error.

  • parallel=true (multi-chain only) — run chains on Threads.@threads.

  • blas_threads=1 — the number of BLAS threads for the duration of the call; the caller's count is restored when the call returns or throws, and nothing leaves BLAS untouched. The count is process-global, so nested and concurrent sampler calls share one setting. Every leapfrog step takes dot products of posterior-length vectors; OpenBLAS runs those on all its threads above 10,000 entries, and its idle workers then busy-wait while the gradient is computed, which takes CPU from the gradient under a CPU quota or with chains on Julia threads. Single-threaded BLAS is also what makes a fixed seed reproduce its draws. Pass a larger count when the target's own gradient spends its time in large BLAS operations and spare cores are available.

  • callback=nothing — observational checkpoint callback (see below).

  • checkpoint_dir=nothing — opt-in on-disk checkpointing (see below).

Checkpoints, callbacks and resume

The warm-up has two checkpoint boundaries: CP-0, right after initialization (Pathfinder), and CP-N, after each outer warm-up window ("big iteration"). Three opt-in, independent mechanisms hang off these boundaries; all default to off, and with them off the run is byte-for-byte identical to the plain sampler.

  • callback=(state, stage) -> should_stop fires at each boundary (stage ∈ (:init, :window)) with the live state. It is observational: it may read state and request an early stop by returning true, but must not mutate state (mutation makes byte-identity the caller's responsibility).

  • checkpoint_dir=path serializes a resumable snapshot at each boundary (cp_init.jls, cp_window_<n>.jls, and an overwritten cp_latest.jls). The snapshot excludes the (possibly non-serializable) inner problem and stores the reparametrizer only as its scalar source centerings. The multi-chain method writes chain i under path/chain_<i>/.

  • stop_requested=() -> Bool opts into stopping inside a window. It is polled before starting/continuing a window and after each complete transition inside it; only literal true stops. The sampler saves cp_latest.jls when checkpoint_dir is set, then returns partial results (possibly zero draws).

  • checkpoint_interval=seconds saves cp_latest.jls at the next poll after a positive finite interval since the last save; it requires checkpoint_dir. Timers are per-chain and reset on resume. Neither option adds callback stages or numbered window files. With either enabled, Treebars interrupts are also polled at these points. Initialization, a single NUTS transition, window finalization, and checkpoint I/O are not interrupted: this is not a hard deadline. Predicates may run concurrently in the multi-chain method and must be thread-safe; they must not mutate sampler state. An unfinished window resumes its remaining budget and adaptation state. Exact continuation requires the same target, sampler configuration, and Julia/dependency/thread settings. Such checkpoints use schema v3 (0.2.14+); completed boundaries retain v2 compatibility. Predicates, intervals, and clocks are call-owned configuration and are never serialized.

  • resume_warmup_mcmc(lpdf, cp_path; ...) re-supplies lpdf and continues from a checkpoint, returning the same result as an uninterrupted run. The multi-chain form takes the parent dir and resumes each chain from its chain_<i>/ subdirectory.

Returns

For the single-chain method, a NamedTuple with fields including initial_position, halo_position, halo_gradient, posterior_position, posterior_gradient, ess, scale_options, active_transformation, stepsize, stepsize_halvings, effective_target_acceptance_rate, total_evaluation_counter, sampling_evaluation_counter, n_divergent_samples, position_and_gradient, scale_changes. For the multi-chain method, a Vector of such NamedTuples.

ess is the per-coordinate bulk ESS of the returned posterior_position, in coordinate order and in the model's own parametrization: ess[k] is the ESS of posterior_position[k, :], and sortperm(ess) lists the coordinates from worst- to best-mixing. It is computed after the back-transform when monitor_ess is on and more than 10 draws are retained; otherwise it is not an estimate for these draws (all zeros when monitoring was off throughout). A constant coordinate's ESS is NaN.

Two evaluation counters, different scopes. total_evaluation_counter is the RUN total over every MCMC transition — the retained epoch's step-size-adaptation transitions and all discarded restart epochs included — but it excludes Pathfinder, the initial step-size search, and the initial evaluation. sampling_evaluation_counter counts only the transitions actually appended to the returned posterior_position (past stepsize_adaptation_limit, in the retained epoch): the exact gradient-cost denominator for min-ESS-per-evaluation over the draws the run keeps.

Deprecated

Resuming is no longer a separate function. Point the sampler itself at the directory instead:

julia
adaptive_warmup_mcmc(rng, lpdf; checkpoint_dir=dir, resume=true)

That form takes its config from the CALL, so resuming with a larger n_draws keeps sampling rather than re-running a fixed-length batch. This function remains for existing callers and is implemented on the same machinery.

Resume adaptive_warmup_mcmc from an on-disk checkpoint written by the checkpoint_dir kwarg. lpdf is re-supplied by the caller (the checkpoint does not store the — possibly non-serializable — inner problem; only the reparametrizer's scalar state is restored onto it). The run continues from the saved boundary.

Config kwargs (n_draws, stepsize_adaptation_limit, …) are accepted here too and default to the same values as adaptive_warmup_mcmc — they are NO LONGER read from the checkpoint, so a resume that relied on the payload carrying the original run's config must now pass it explicitly.

WarmupHMC.rescore_warmup_checkpoint Function
julia
WarmupHMC.rescore_warmup_checkpoint(lpdf, payload; rtol=1e-10)

Return an independent adaptive checkpoint with its current log density and all retained pointwise gradients evaluated on lpdf. Use this explicitly before resuming on another CPU; ordinary resume keeps its existing replay behavior. Supply the same target, data and reparametrization structure as the original run. Saved controls are applied privately, leaving the caller's controls alone.

Every old/new live log density and gradient component must be finite and obey abs(new - old) <= rtol * max(abs(old), 1). Retained positions and new log densities must also be finite. rtol must be finite and nonnegative; zero requires numerical equality. A mismatch throws ArgumentError with the largest scaled deviation and its field, column and coordinate (zero denotes the live scalar). The supplied payload is unchanged on success or failure.

Refreshes position_and_gradient, posterior_gradient, halo_gradient, and occupied nonlinear leaf-sample gradients. Preserves RNGs, counters, window phase, metric, dual averaging, accumulated moments and candidate losses. Dropped-epoch snapshots are inert and remain in their original frame. This is tolerance-checked continuation, not trajectory replay or proof of target identity: compressed history cannot be reconstructed from retained points.

Appends an audit to rescored, preserved by subsequent checkpoints. Its evaluation count is separate from sampler counters. Work is one target evaluation per retained point plus O(dimension × retained points) vector work and an independent payload copy; no dense adaptation matrix is constructed.

Cooperative chains ​

WarmupHMC.cooperative_warmup_mcmc Function
julia
cooperative_warmup_mcmc(rng, lpdf; n_chains=4, n_cores=n_chains, target_ess=Inf,
    rhat_threshold=1.01, n_evaluations_budget=typemax(Int), time_budget=Inf,
    n_draws=typemax(Int), kwargs...)

Cooperative multi-chain NUTS warm-up and sampling on one target: n_chains chains adapt TOGETHER and keep sampling until a stopping bound is met.

Every leapfrog state of every chain feeds running position and gradient moments. Chains pool them through soft clusters (chains near each other in the posterior share; once they have mixed, all share one estimate), and each chain's metric is the Nutpie diagonal scale of its pooled moments. Work proceeds in rounds of n_evaluations gradient evaluations per chain; batch k is 2^(k-1) rounds. At a batch end a chain restarts warm-up under its pooled estimate only when that estimate's relative condition number against its current metric, times the predicted step-size gain, exceeds restart_threshold (2). A restart drops the chain's draws; otherwise it keeps sampling under its fixed kernel, so every kept draw is an MCMC draw of an unchanging kernel. Step sizes follow a per-chain fit of acceptance ≈ 2Φ(-κε²) with the pooled κ as prior. No chain is ever parked or abandoned.

  • rng seeds every chain: chain i's stream is drawn from it when chain i is created, so one seed reproduces the run at any thread count.

  • Stops on target_ess when the pooled ESS of at least min(2, n_chains) chains reaches it AND the maximum rank-normalized split R-hat over every retained history is below rhat_threshold (default 1.01, finite and > 1). Both checks use the returned model frame. R-hat uses all draws, even with unequal history lengths: split-chain variances and means have equal weight, and odd histories retain their middle draw. The maximum includes both ordinary rank-normalized values and ranks of absolute deviations from the pooled median (folding). Every nonempty chain needs more than 10 draws; empty chains do not contribute. This diagnostic cannot detect an unvisited mode.

  • Also stops when n_evaluations_budget gradient evaluations are spent, time_budget seconds pass, every chain holds n_draws draws, or Treebars.request_interrupt! is called on progress, all checked at round barriers (a budget or an interrupt also stops a round early). At least one bound must be finite. The returned stop_reason names the one that fired. The target_ess stop needs monitor_ess (the default).

  • init (as for adaptive_warmup_mcmc) is shared by every chain, or a vector of per-chain inits; a position vector of reals is one shared start.

  • blas_threads=1 holds BLAS at that many threads for the whole call and restores the caller's count afterwards, as for adaptive_warmup_mcmc; nothing leaves BLAS untouched.

Checkpointing and resume

checkpoint_dir=path writes, at every round barrier, path/run_latest.jls (the whole run) and path/chain_<i>/cp_latest.jls, plus path/chain_<i>/cp_window_<k>.jls at the end of batch k, all atomically; run_manifest.json at the start and run_summary.json at the finish are write-once. A later call with resume=true continues an unfinished run from its last round barrier: every chain's state, draws and stream, the seed RNG, the clusters and the counters are restored, so the run continues as if it had not stopped. The configuration comes from the resuming call (a larger n_draws extends finished chains; n_chains must match), the evaluation budget continues from the restored total, and time_budget from the run's live time. A finished run (run_summary.json exists) is refused; overwrite=true discards the directory's run.

Returns (; results, stop_reason, n_used, joint_ess, n_pooled, n_batches, total_evaluation_counter, elapsed). results[i] is chain i's chain_result, its draws in the model frame. joint_ess is the pooled ESS over the n_pooled chains with the most draws (at least min(2, n_chains)).

Completion policy ​

WarmupHMC.completion_warmup_mcmc Function
julia
completion_warmup_mcmc(rngs, lpdf_or_lpdfs; min_completed=length(rngs),
    n_draws=1000, stuck_stepsize_ratio=10, max_admitted_divergent_fraction=0.1,
    checkpoint_dir=nothing, resume=false, overwrite=false, kwargs...)

Opt-in completion quorum over independent adaptive_warmup_mcmc chains. For example, pass 16 RNGs and min_completed=12 to request that unfinished chains finish their current round when the twelfth full chain returns. Every chain completing its requested production draws during that final round is retained too, in original index order, unless it is stuck (below). The call returns once all workers settle. The default samplers and their return types are unchanged.

Stuck chains are left out. Reaching n_draws first is no evidence of health: a chain whose step size collapsed, or whose transitions diverge, takes short, cheap trajectories and can finish before every healthy chain. A chain that reaches n_draws counts toward min_completed only if

  • at most max_admitted_divergent_fraction of its retained draws diverged, and

  • its step size is at least 1/stuck_stepsize_ratio of the median latest step size of its siblings that are keeping draws at that point. Both are the step sizes adaptation chose, before any opt-in halving (divergence_tolerance): a halving answers divergences, which the first check judges.

Otherwise its status is :stuck: it is omitted from results and does not count, so the quorum waits for chains that pass. While no sibling keeps draws yet, a finished chain waits uncounted and is judged as soon as one does; if none ever can, it is admitted. A verdict is final once made. Neither check looks at where a chain's draws are, so a chain that samples a different mode without collapsing or diverging is kept, and the step-size check cannot catch a run in which every chain collapsed together. stuck_stepsize_ratio=Inf and max_admitted_divergent_fraction=1 switch the checks off.

Each chain runs the ordinary adaptive procedure with its own deep-copied density, initialization and RNG slot. There is no cross-chain adaptation. init accepts the adaptive multi-chain per-chain forms. Other kwargs are adaptive single-chain keywords, including callback(state, stage): returning true there stops only that chain and does not count an incomplete chain. Treebars.request_interrupt! behaves the same way through the progress tree: on one chain's node it stops that chain, on the node passed as progress (or an ancestor) it stops every running chain and starts no further slot. Callbacks may run concurrently and must be observational and thread-safe. blas_threads=1 holds BLAS at that many threads for the whole call, every chain included, as for adaptive_warmup_mcmc; nothing leaves BLAS untouched. progress= builds one quorum parent node — chains completed of min_completed, the stop state, and the stopped/never-started/failed slots — with one "<description>.<i>" child subtree per original chain slot, as multi-chain adaptive. A worker that never starts leaves no child; its slot is named by the parent's labels instead.

Quorum requests a cooperative stop at the next checkpoint boundary. An active initialization or adaptive window must finish; this is not a hard wall-time limit. A worker that has not started at quorum does not start. No tasks are interrupted or detached, and every worker is joined before return. There is no grace period or admission cutoff: a full result is always retained. Julia threads are required for simultaneous CPU work; runtime selection and completion order are not reproducible from RNG seeds alone.

Returns (; results, completion). Only admitted full chains appear in results, each carrying the adaptive result fields plus original chain_index and actual n_samples. completion records policy and the two admission thresholds, requested/started/completed/failed/stuck/omitted identities, all chain dispositions and captured errors, quorum and stop-request times (seconds since worker scheduling begins), and retained draw/divergence counts. Each completion.chains[i] of a chain that reached n_draws also records its adapted stepsize (before any halving; the result's own stepsize is the one it sampled with), divergent_fraction, the reference_stepsize it was compared with (nothing when it was not compared: no sibling ever kept draws, the step-size check is off, or the divergence check already left it out), and, for a stuck chain, stuck_reason (:divergence or :stepsize). A failed chain's n_samples is nothing because it has no finalized result; its n_retained_samples is zero. Failed and stuck chains are also omitted. If the quorum is unmet, throws WarmupHMC.CompletionQuorumError with this same outcome; partial results are never silently reported as a successful fit.

Inferential limitation: selecting faster chains can bias inference when runtime depends on sampled states or modes. R-hat, bulk/tail ESS and divergence checks describe only the returned draws and cannot rule out that bias. The call @warns this caveat after the chains settle, and records it in completion.selection_warning, when the retained chains are such a selection: at least one chain was kept and some other slot was stopped short of n_draws (by the quorum, a callback or an interrupt) or never started. Otherwise selection_warning is "" and nothing is printed: with min_completed = length(rngs), or when every chain finished anyway, the returned draws are those of all-chain sampling. Chains left out as stuck or failed do not make a selection; they are named in stuck_chain_indices and failed_chain_indices. Report the policy and all omissions; do not describe the requested count as completed. Use all-chain sampling when this selection is unacceptable.

Checkpoint files remain ordinary adaptive source-frame state under original chain_<i> directories. resume=true requires the same ordered RNG/density slots; existing checkpoints restore their saved RNG, while a slot that never checkpointed initializes from the supplied RNG. Re-pass original sampler settings. For an interrupted run, already-complete checkpoints are judged deterministically before workers launch, against every slot's latest checkpointed step size; no incomplete worker starts if the admitted ones already meet quorum. A successful terminal run reopens its recorded outcome, and warns iff its recorded selection_warning is non-empty (always, for runs recorded before the caveat followed the outcome): it never samples or admits omitted chains, and changing n_draws, min_completed, the admission thresholds or the slot count is rejected. A run recorded before the admission checks existed reopens as recorded, whatever thresholds are passed. This includes terminal runs saved under the older grace/cutoff policy: their recorded selection and metadata are preserved, not reinterpreted. Omit the removed grace_seconds keyword when reopening them. An unfinished legacy run resumes using the new finish-current-round policy. Extend individual adaptive checkpoints separately when a different production target is required. completion_manifest.jls binds the original slot count; each invocation writes its own run_manifest.json (whose selection_warning carries the caveat when min_completed is below the slot count, "" otherwise) and, after all workers settle, run_summary.json under completion_attempts/attempt_<n>/. The returned completion.attempt_directory identifies that invocation. completion_terminal.jls stores the successful outcome, including returned draws, atomically before the summary is published. These run records do not change chain payloads.
