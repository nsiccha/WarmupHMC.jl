Streams and transitions ​

The signatures below use placeholder arguments and are not standalone programs. The changing-target example executes the fixed-kernel interface.

Persistent streams ​

WarmupHMC.stream_mcmc Function
julia
stream_mcmc(rng, lpdf, position; path, n_draws, metric, stepsize, kwargs...)
stream_mcmc(lpdf; path, n_draws, metric, stepsize, kwargs...)               # resume-only
stream_mcmc(checkpoint, lpdf; path, n_draws, kwargs...)                     # seed from a WarmupHMC checkpoint
stream_mcmc(checkpoint, lpdf, position; path, n_draws, rng, kwargs...)      # checkpoint kernel, explicit start
stream_mcmc(checkpoint, lpdf, positions; path, n_draws, rngs, parallel)     # N chains under path/chain_<i>
stream_mcmc(rngs, lpdf, positions; path, n_draws, metric, stepsize)         # N chains, explicit kernel

Fixed-kernel, interruptible, resumable NUTS sampling — pure sampling with NO warm-up and NO adaptation. Streams draws into the mmappable Float64 file at path (zeroed at creation, draws as COLUMNS, dimension × n_draws, in the sampler's raw SOURCE frame) while continuously persisting only (rng, last-safe-draw, dimension) into a crash-safe "safe ring" at path * ".ring" — the current position is NOT re-stored, it is read back from the samples file on resume. A process killed mid-sample or mid-write resumes from the immediately preceding state.

Resuming

Pass the same path. If it holds a valid ring it is RESUMED: the rng comes from the ring, the position is read from the file's last safe column, and only the kernel hyperparameters are taken from the call. n_draws is a FLOOR — resuming with a larger value extends the file (new columns zeroed) and keeps sampling; a value at or below what is already written returns the existing draws. overwrite=true discards an existing run and starts fresh. A crash inside the very first transition (before draw 1) leaves an unresumable file that restarts from the caller's seed — no draw is ever lost.

The start position, or on resume the last stored draw, is evaluated under the supplied lpdf and must lie inside its support: a -Inf log density there raises an ArgumentError saying so. A leapfrog position outside the support is an ordinary divergence instead.

Resuming a run that predates a per-draw sidecar (.divergences / .rng_states) creates that file zeroed and keeps sampling, but emits a @warn: the already-drawn columns cannot be reconstructed, so draws 1..n_written read back as zeros (not their true divergence flag / RNG state); only draws from the resume point forward are recorded truthfully.

Kernel hyperparameters (never persisted — supplied every call, or read from a checkpoint)

  • metric — the mass-matrix SCALE L (L*L' ≈ posterior covariance): a Diagonal/matrix/WarmupHMC matrix expression, a vector of per-coordinate scales (std devs), or a ready DynamicHMC.GaussianKineticEnergy. A warm-up scale (checkpoint's scale_options[active_transformation]) plugs in directly. Any square matrix is accepted. A Diagonal, triangular or WarmupHMC matrix expression is applied as given; any other matrix (a plain dense Matrix, Symmetric, …) is copied, wrapped as LowerTriangular/UpperTriangular when its entries are triangular, and otherwise replaced by cholesky(Symmetric(L*L')).L. The kernel depends on L only through L*L', so that replacement samples the same Markov chain law, though a seed's momentum draws differ from those of L itself.

  • stepsize — the fixed leapfrog step size.

  • max_tree_depth=10 — NUTS max tree depth.

Streaming config

  • path — the mmappable samples file. Required.

  • n_draws — number of draws (sizes the zeroed file); a floor on resume.

  • durable=false — false streams to the page cache (survives a PROCESS crash, the resume contract). true Mmap.sync!s each draw to disk before the ring points at it (survives a MACHINE/power crash too, at one msync per draw).

  • overwrite=false — start fresh over an existing path.

  • progress=nothing / description="stream_mcmc" — a Treebars node to hang a progress tree under (as adaptive_warmup_mcmc). It reports only the NON-fixed quantities — draws done, this session's draw rate, divergences, mean leapfrog steps per draw, and bulk-ESS recomputed on exponential (doubling) windows. The step size and metric are fixed and deliberately not shown. nothing runs with zero progress/ESS overhead.

Output frame

The file and the returned draws are the SOURCE (working) frame — the sampler's own parametrization, which is what resume reads back. Constrained model-frame draws are produced on READ: open_stream(path, lpdf; model=true), or WarmupHMC.back_transform. For a plain log density the frames coincide, so the file is already the posterior draws.

Seeding from a WarmupHMC checkpoint

stream_mcmc(payload, lpdf; ...) (or a cp_*.jls path) reads the RNG, current position, mass-matrix scale and step size out of the payload — the final adapted kernel of a warm-up run — restores its reparametrization centerings onto lpdf, and streams from there. lpdf must be built exactly as the run was given it.

Passing an explicit position keeps the checkpoint's KERNEL but overrides its start point (e.g. an equidistant warm-up draw), with rng inheriting the checkpoint's unless given. Passing a VECTOR of positions fans out one independent chain per start point, each an interruptible/resumable stream under path/chain_<i> (+ its .ring); re-calling the same path resumes every chain. parallel=true threads them under a shared progress bar; rngs defaults to N independent streams derived from the checkpoint's rng; lpdf is deepcopied per chain (pass a length-N vector of lpdfs to override) so a stateful wrapper never races. stream_mcmc(rngs, lpdf, positions; metric, stepsize, ...) is the same fan-out with a hand-supplied kernel. Multi-chain returns a Vector of per-chain result NamedTuples.

Returns a NamedTuple: path, draws (a view of the dimension × n_drawn mmapped source-frame draws), samples (the live mapping), n_drawn, n_divergent (of this call), divergences (a length-n_drawn Int8 0/1 view of EVERY draw's divergence flag — their sum is the total), rng_states (a 5 × n_drawn UInt64 view of every draw's post-draw Xoshiro state), ess (per-coordinate bulk-ESS of draws, in coordinate order — ess[j] is the ESS of draws[j, :]; NaN for <= 10 draws), dimension, rng, position. Reopen a finished or partial run with open_stream. Call close_stream on each result once its mapped views are no longer needed, before removing the stream files on Windows.

Every method takes blas_threads=1: BLAS runs with that many threads for the whole call and gets the caller's count back afterwards, as for adaptive_warmup_mcmc; nothing leaves BLAS untouched. Resume-equals-uninterrupted is byte-for-byte for a fixed seed only under single-threaded BLAS, which is the default.

WarmupHMC.open_stream Function
julia
open_stream(path) -> NamedTuple
open_stream(path, lpdf; model=false) -> NamedTuple

Reopen an stream_mcmc run (finished or in-progress) for READING. Reads (rng, n_written, dimension) from the safe ring at path * ".ring", then memory-maps the samples file and returns draws — a dimension × n_drawn view, draws as COLUMNS — plus samples (the read-only mapping), n_drawn, dimension, rng, and the source-frame position (the last drawn column). Also returns the per-draw sidecars divergences (a length-n_drawn Int8 0/1 view) and rng_states (a 5 × n_drawn UInt64 view of the post-draw Xoshiro state) — each nothing for a run that predates them.

The stored draws are the SOURCE (working) frame. Pass lpdf and model=true to get constrained model-frame draws instead (draws is then a fresh Matrix{Float64}, back-transformed exactly as WarmupHMC.back_transform); with model=false the lpdf is used only to check the dimension. Throws if path has no readable safe ring.

Call close_stream on the returned value before deleting the stream files, especially on Windows. The returned views become invalid after closing.

WarmupHMC.close_stream Function
julia
close_stream(result) -> nothing

Release the memory mappings held by a result from stream_mcmc or open_stream. Call this after copying any needed draws, sidecar values, or position and before removing or replacing the stream files on Windows. The result's samples, draws, rng_states, and divergences views must not be accessed after closing. Calling close_stream again is harmless.

stream_mcmc closes its safe-ring file handle before returning; the mapped arrays are the resources this function releases. The on-disk stream remains resumable and can be reopened with open_stream.

Fixed kernel ​

WarmupHMC.FixedKernelNUTSState Type
julia
FixedKernelNUTSState(rng, position; metric, stepsize, max_tree_depth=10)
FixedKernelNUTSState(checkpoint; max_tree_depth=10, position=..., rng=...)
FixedKernelNUTSState(state::FixedKernelNUTSState; position=state.position, rng=state.rng)

In-memory state for fixed_kernel_nuts_step. position is in the sampler's source frame. metric is the mass-matrix scale accepted by stream_mcmc, not a covariance or precision matrix. A checkpoint payload (or its file path) supplies its final position, RNG, learned scale, step size and reparametrization controls; position and rng can override its start point and random stream.

Construction does not evaluate a target. Each step evaluates the current target at the stored position, so the target may change between calls while the kernel remains fixed. State creation and stepping do not write files. The position, RNG and metric are copied when the state is created.

The third form starts a new chain on an existing state's kernel: it takes its own copies of position and rng and shares state's metric, step size, tree depth and reparametrization controls, which nothing mutates. N particles built this way from one state hold one kernel instead of N, and may be stepped concurrently. Pass each particle its own rng: the default continues a copy of state's stream, so two states that keep it draw the same momenta.

WarmupHMC.fixed_kernel_nuts_step Function
julia
fixed_kernel_nuts_step(state::FixedKernelNUTSState, lpdf; blas_threads=1)

Take exactly one fixed-kernel NUTS transition under the supplied LogDensityProblems target. Return (; state, divergent, stats), where state is the next in-memory state, divergent is this transition's divergence flag, and stats is the DynamicHMC tree statistics. The input state is not advanced. Read the new source-frame position from result.state.position.

The target may change on every call, but must keep the same dimension and source-coordinate frame. Its log density and gradient are freshly evaluated at the saved position before sampling. If the new target puts that position outside its support (log density -Inf), the step raises an ArgumentError saying so; a NaN or +Inf log density, or a non-finite gradient, there fails DynamicHMC's evaluation. At a leapfrog position, by contrast, leaving the support is an ordinary divergence, and the gradient at such a point is never read. A checkpoint's adapted reparametrization controls are restored onto a private copy of each supplied target. The fixed metric, step size and tree depth are not adapted. Mixed-target positions are not a stationary posterior sample and must not be pooled for ESS.

The transition runs with blas_threads BLAS threads and restores the caller's count afterwards, as for adaptive_warmup_mcmc; nothing leaves BLAS untouched.

Continuous adaptation ​

WarmupHMC.ContinuousNUTSState Type
julia
ContinuousNUTSState(rng, lpdf; init=missing, target_acceptance_rate=0.8,
                    max_tree_depth=10, half_life=20, prior_weight=10,
                    pathfinder_kw=(;), blas_threads=1)

In-memory state for continuous_nuts_step: a NUTS chain whose diagonal metric and step size keep adapting on every transition, for a target that changes between transitions. Initialization is adaptive_warmup_mcmc's: init takes every form documented there, so by default Pathfinder runs from a random start on lpdf, a vector init runs Pathfinder from it (from a jitter of it when it is a stationary point such as a mode; the init section of adaptive_warmup_mcmc), and init = (; position, squared_scale) starts exactly there with that diagonal covariance. The start position and the diagonal of the initializer's covariance give the first metric; DynamicHMC's initial step-size search gives the first step size. A Pathfinder start is a point at which lpdf is finite: a draw a bounded support excludes is redrawn from the fit, and failing that an L-BFGS iterate stands in. A fit far wider than the target (a collapsed variance beside normal ones) gives neither the start nor the metric: Pathfinder runs again on the target rescaled by a diagonal from its L-BFGS trajectory (see adaptive_warmup_mcmc's init). Construction evaluates lpdf for Pathfinder (twice for such a fit), for the start (once per draw tried) and for that search, nothing else.

half_life is the memory of the metric evidence, in transitions: the leapfrog states of a transition half_life transitions ago weigh half as much as the current one's (Inf never forgets). prior_weight is how many leapfrog states the start scale is worth; it forgets at the same rate. target_acceptance_rate is the step size's target. pathfinder_kw is forwarded to the Pathfinder initializer. blas_threads is held for the construction as for every sampler.

Fields a caller reads: position (the current position, in the target's coordinates), scale (the metric, a Diagonal; scale * scale' is the estimated posterior covariance), stepsize, rng, n_transitions, total_evaluation_counter and n_divergent. The state is advanced in place by continuous_nuts_step and moved by reposition!.

WarmupHMC.continuous_nuts_step Function
julia
continuous_nuts_step(state::ContinuousNUTSState, lpdf; adapt=true, blas_threads=1)

Take one NUTS transition under the supplied LogDensityProblems target and, with adapt=true, adapt the state's diagonal metric and step size to what the transition saw. Return (; state, divergent, stats): state is the same object, advanced in place; divergent is this transition's divergence flag; stats is DynamicHMC's tree statistics (steps counts the gradient evaluations). Read the new position from state.position.

The target may change on every call, but must keep the same dimension and coordinate frame. Its log density and gradient are freshly evaluated at the saved position (the last transition's, or the one reposition! stored) before sampling; a position the new target puts outside its support (log density -Inf) is an ArgumentError saying so, and a NaN or +Inf log density or a non-finite gradient there fails DynamicHMC's evaluation. At a leapfrog position, leaving the support is an ordinary divergence, and the gradient at such a point is never read.

Adaptation, per transition: the evidence forgets by the state's half-life; every good leapfrog leaf of the transition feeds position and gradient moments; the metric becomes the diagonal scale (var(position) / var(gradient))^(1/4) of those moments, shrunk toward the start scale by the remaining prior weight; the step size and its (ε, acceptance) history are carried through the metric change by the geometric mean of the scale change; then the step size moves toward target_acceptance_rate through the κ fit of the recent pairs, halved after a transition that accepted less than 10 %. adapt=false takes the transition under the current kernel and changes nothing but the position: the same draw a FixedKernelNUTSState with that kernel takes.

Positions from different targets are not a stationary posterior sample. The transition runs with blas_threads BLAS threads and restores the caller's count afterwards; nothing leaves BLAS untouched.

WarmupHMC.reposition! Function
julia
reposition!(state::ContinuousNUTSState, position::AbstractVector)

Translate the chain to position and leave its kernel alone. A caller that moves the target and the chain together calls it instead of building a new state: SAEM's mu-referenced re-centring shifts each subject's η after an M-step that moved θ, so that φ = Dθ + η stays where it was, and a translation of the target leaves the metric and step size valid. The saved position and the mean of the position evidence move by the same vector, so the leapfrog states the metric is estimated from are translated with the chain (their spread, the gradient evidence, and so the metric, are what they were); scale, stepsize, the forgetting, the κ fit, rng, n_transitions and the counters stay. A translated target sampled by the translated chain is therefore the same chain, draw for draw up to rounding. Rebuilding the state through init = (; position, squared_scale) would instead restart the metric evidence from prior_weight pseudo-states and run DynamicHMC's step-size search again, and leaving the position evidence where it was would inflate the metric by the move until it is forgotten.

position is copied (any real AbstractVector of length state.dimension; a wrong length is a DimensionMismatch, a non-finite entry an ArgumentError, and a refused move changes nothing) and not evaluated: the next continuous_nuts_step evaluates it under the target it is given, and a position that target excludes is that call's ArgumentError. Returns state.
